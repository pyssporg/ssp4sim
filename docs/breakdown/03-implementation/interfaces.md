# Interfaces

A deliberately small public API, a runtime-control contract shared by the C, C++, and Python surfaces, and a separate local daemon protocol.

- **Public API:** `src/lib/public_include/` holds `cpp_api/simulator.hpp` (C++ caller-facing `Simulator` facade, which delegates to the internal `SimulationRuntime` that owns the run thread, `RunControl`, and the outer loop, plus one blocking snapshot call, with the `Simulator(const std::string& config_path)` convenience constructor and the object-first `Simulator(SharedConfig config, Logger* = nullptr)`, plus `init`, `start` (blocks until running or terminal), `pause`, `resume`, `stop`, `set_speed`, `info`, `wait`, `simulate`, `snapshot`, `restore`, `reset`), `cpp_api/simulator_core.hpp` (synchronous C++ `SimulatorCore`: `init`, `start`, `step`, `advance_to`, `sim_time_ns`, `end_time_ns`, `finish`, plus `save_snapshot` and `load_snapshot` for whole-simulation checkpoints; no thread, pacing, pause, or speed), `c_api/simulator_c_api.h` (threaded C wrapper mirroring the C++ surface: `ssp4sim_simulator_create`, `init`, `simulate`, `start`, `pause`, `resume`, `stop`, `reset`, `set_speed`, `get_info`, `wait`, `snapshot`, `restore`, `destroy`; control calls take `ssp4sim_simulator_handle *`, `get_info` returns `ssp4sim_run_info` by value (a null handle returns the zero/default record and sets `ssp4sim_last_error()`), and `wait` writes an `ssp4sim_run_result`), `c_api/simulator_core_c_api.h` (synchronous C wrapper over `SimulatorCore`: `ssp4sim_simulator_core_create`, `init`, `start`, `step`, `advance_to`, `get_info`, `finish`, `destroy`; no thread, pacing, pause, or speed, and callers must `finish` before `destroy` to flush recording), `c_api/c_api_common.h` (`ssp4sim_status`/`SSP4SIM_STATUS_*` and `ssp4sim_last_error`, included by both C headers), `runtime_control.hpp` (public `RunState`/`RunResult` enums and the `RunInfo` type), and `shared_config.hpp` (per-instance `SharedConfig` value with the `from_file`, `from_string`, and `from_json` factories, each taking an optional `Logger*`).
- **Coherent read:** `RunInfo { RunState state; uint64_t sim_time_ns; double speed; }` is the sole public read-back and its fields agree with each other; it is exposed as C++ `Simulator::info()`, C `ssp4sim_simulator_get_info()` (returns `ssp4sim_run_info` by value; a null handle returns the zero/default record and sets `ssp4sim_last_error()`), and Python `info()`.
- **One-shot convenience:** `simulate()` is exactly `start()` followed by `wait()`; its blocking behaviour and exception mapping are unchanged (`REQ-009`).
- **Terminal results:** C++ and Python `wait()` return `Completed`/`completed` or `Stopped`/`stopped` and raise on a failed run; the C ABI `ssp4sim_simulator_wait` returns `SSP4SIM_OK` for Completed or Stopped and writes the `ssp4sim_run_result`, while a failed run returns `SSP4SIM_RUNTIME_ERROR` with `ssp4sim_last_error` set, never a failed result with `SSP4SIM_OK`.
- **Runtime control:** lifecycle, speed, scheduling of lifecycle/speed commands, state, simulation-time/speed read-back, and wait are promised by `REQ-016` and implemented in the control module (`INFO-023`). `start` blocks until the run leaves initialized (running or terminal). Terminal states are monotonic; `stop` is idempotent once stopping or terminal, preserves partial results, and is an error before the run starts, while the teardown path cancels a pre-run state to stopped. A completed run publishes the configured end time after the recorder flush. `pause`, `stop`, and `set_speed` take an optional `at_sim_time_ns` (C ABI: `int has_at_sim_time, uint64_t at_sim_time_ns`) that defers the command to the first macro-step boundary at or after that time; `resume` is not schedulable. Variable overrides (`set_override`, `clear_override`, `list_overrides`), the override target validation, and `y = k*x + m` behavior are planned/deferred and not in current releases.
- **Control daemon:** `src/public/ssp4sim_server/` implements `ssp4simd`, a frontend that relays lifecycle, speed, and checkpoint control over newline-delimited JSON on a Unix domain socket (`REQ-017`, `INFO-011`, `INFO-010`); it is not part of the engine API. The daemon owns an async snapshot worker and request queue; each request calls the blocking `Simulator::snapshot`, which posts one private `SnapshotWork : RunThreadTask` through the single time-sorted queue inside `RunControl`, consumed by the run worker at the macro-step boundary; the same queue and consume point serve `Running` and `Paused`. Control commands (`pause`, `resume`, `stop`, `set_speed`) stay in `RunControl` because they decide whether the loop may proceed and must interrupt pacing. `start` stays on the poll thread; `reset` and `restore` reply `accepted`, then run one background lifecycle thread that quiesces the old runner and rebuilds through `Simulator::rebuild` (which quiesces the old runner through `Simulator::shutdown` and `SimulationRuntime`), and the poll thread swaps the runner and emits a `lifecycle` event (`operation`, `ok`, and either `state`/`sim_time` or `code`/`error`). While that job runs, mutating commands return `server_busy`; `state` and `shutdown` remain available. Pending snapshot work is settled before the swap (the worker is joined first), and the background thread is the only waiter on the old runner until the handoff. Checkpoint commands are `snapshot` (push onto the daemon request queue and always reply `accepted`; the worker completes it and the poll thread reports one `snapshot` event carrying the request `id`, `code`, and success/failure fields; multiple requests may be queued) and `restore` (rebuild, validate, apply, optional start). When `SharedConfig::snapshot_dir` (`simulation.snapshot.directory`) is set, the daemon canonicalizes it once and rejects `snapshot`/`restore` paths outside it with `bad_value`. Override commands are planned/deferred.
- **Snapshot contract:** `Simulator::snapshot(path)` is one blocking call legal only in `Running` or `Paused`: it creates a shared promise and posts a private `SnapshotWork : RunThreadTask` onto the single queue inside `RunControl`, then waits on the future. The run worker executes `SimulatorCore::save_snapshot` at the macro-step boundary, or the queue settles the work as a `SnapshotError("run_ended", ...)` when the run ends first. `SimulatorCore::save_snapshot`/`load_snapshot` own the format and validation; no snapshot service, result channel, correlation, drain, or wait-for accessor exists in the library. During a daemon lifecycle job the background thread owns the old simulator's `shutdown()`, so `monitor_tick` never waits while the job is busy; the poll thread stops and joins the snapshot worker and swaps to the prepared runner only after the handoff under `lifecycle_mutex_`. Restore/rebuild go through `Simulator::rebuild`: `SimulationRuntime` owns the run thread and loop; `SimulationRuntime::shutdown()` returns the old run's failure text, cancels a pre-run state to Stopped, and joins a started run, `Simulator::shutdown()`/`Simulator::rebuild` delegate to it, and `Simulator::rebuild` quiesces the old simulator and builds the replacement through the private `Simulator::create_initialized`/`create_restored` factories, taking an optional snapshot path (null = reset, non-null = restore), with `RebuildResult` carrying the replacement simulator or the preserved exception/message; `Simulator::restore` rethrows the preserved failure while the daemon converts it to its event. `Simulator::restore` retains the original config across the swap, so repeated restores derive from the creation config. The private `Simulator::prepare_restore_config(SharedConfig, double prior_speed)` helper carries the prior pace and redirects CSV output to a new `<stem>.restored-<uuid><ext>` segment. A v4 checkpoint is one little-endian file (`SSP4SNAP`, format 4): a 28-byte header (magic, u32 version, u64 manifest size, u64 content checksum) followed by a JSON manifest and a payload that concatenates self-serialized sections in manifest order. The manifest carries `ssp_hash`, `sim_time_ns`, and a `sections` array. Each section entry is `{"kind":"model","name":"<graph model key>","offset":N,"size":M}` for one live FMU model or `{"kind":"frontiers","offset":N,"size":M}` for the single resolver-frontier section; offsets and sizes are relative to the payload. The private `simulation/serialize` module owns `Writer`/`Reader`, size/count codecs, vector and masked-blob helpers, field matching, validated text codecs (`write_text`/`read_text` reject NUL and invalid UTF-8), and keyed `StringTable`s for arbitrary string collections; parts implement only `ISerialize::serialize`/`deserialize` over their domain fields. A model section is the FMU model's own `ISerialize` output (identity strings, current time, FMI 2.0 state blob, and its input/output `SignalStorage` sections), and the frontiers section is the resolver's `ISerialize` output. String-valued signal storage is carried inside the model storage sections as typed string values with zeroed binary ring byte ranges; restore destroys and reconstructs the live `std::string` objects before swapping the saved values in; invalid UTF-8 or an embedded NUL fails as `unsupported`. Only the current format version is readable; older versions are rejected. Saves write a `<target>.part-<uuid>` temp sibling, fsync the temp file strictly, rename atomically, and attempt a best-effort parent-directory fsync, so a failed save never truncates a good checkpoint; the 28-byte header carries an FNV-1a 64 checksum over the manifest and payload, and the SSP content hash is cached per runner. Load validates the SSP content hash (path-independent), checksum, the section table (known kinds only, unique model names exactly matching the live model set, exactly one frontiers section, offsets/sizes inside the payload), and FMU state capability (`canGetAndSetFMUstate` + `canSerializeFMUstate`) before mutating anything; it then applies each model section with `deserialize` followed by `expect_end`, the frontiers section the same way, and `sim_time_ns` last. A part failure raises `apply_failed`; a table or file-identity failure raises `invalid_snapshot`; an apply failure leaves the target `SimulatorCore` unspecified, so the caller discards it and builds a fresh one; the event queue is closed under `RunControl`'s mutex. The blocking public surface is `Simulator::snapshot`/`restore`/`reset` (C++), `ssp4sim_simulator_snapshot`/`restore`/`reset` (C), and Python `snapshot`/`restore`/`reset`; the daemon adds the asynchronous worker and request-`id` correlation, without progress events. `reset` destroys the old simulator and swaps in a freshly built initialized one, clearing per-run state.
- **Invocable:** `src/lib/include/execution/invocable.hpp` — abstract init()/invoke(data); implemented by FmuModel and other invocable objects.
- **ExecutionBase:** `src/lib/include/execution/executor.hpp` — abstract executor managing the model vector; the interface for Jacobi/Seidel variants (`INFO-023`).
- **Graph nodes:** `InvocableNode` marker interface for schedulable graph nodes, `src/lib/include/graph/graph.hpp`.
- **Recorder interface:** `DataRecorder::add_storage()` and `add_sink()`; `RecorderSink` abstract `start()`/`on_event()`/`stop()`; implementations `CsvRecorderSink` and `SqliteWALRecorderSink` — signal module (`INFO-024`).
- **Boundary:** these contracts satisfy the container boundaries (`INFO-011`); the config access pattern is the configuration leaf (`INFO-017`).
