# execution module

Provides executor strategies that advance simulation time and coordinate FMU stepping, selected by configuration, plus the run-control state machine that starts, pauses, resumes, stops, and paces a run.

- **Role:** `ExecutionBase` defines the executor interface; `ExecutorBuilder` creates the configured executor; strategy pattern, one concrete strategy per algorithm. Executors are pure time-step runners: `SimulationRuntime::run()` owns the outer macro-step loop, calls `RunControl::next_action()` at each step top, calls `SimulatorCore::step()` for one configured step, and invokes the executor on that step.
- **Engine split:** `Simulator` (`src/lib/public_include/cpp_api/simulator.{hpp,cpp}`) is the caller-facing facade: it retains the creation config, exposes start/pause/resume/stop/set_speed/info/wait/shutdown plus the blocking `snapshot`/`restore` entry points and `reset`, and delegates to the internal `SimulationRuntime` (`src/lib/include/simulation/runtime/`), which owns the run thread, `RunControl`, pacing, `RunState`, start barrier, `wait`, terminal result, and the outer loop. `SimulatorCore` (`src/lib/public_include/cpp_api/simulator_core.{hpp,cpp}`) is the synchronous core: SSP import, graph, executors, recorder, simulation time, one macro step, and `advance_to` for exact-time callers. `src/lib/include/simulation/runtime/run_control.{hpp,cpp}` holds `RunControl`, the single locked queue and status object: one mutex and one condition variable guard the lifecycle state, one `std::multimap` of commands and run work sorted by due time and insertion order, a closed flag, and the lock-free `PacingClock` collaborator (simulation time, speed, pacing anchors, monotonic advance, deadline math). Queue and state access share the same lock. Guarding them together keeps post-vs-close and state reads coherent, and `next_action()` remains the single loop gate returning `LoopAction`; immediate control calls still change state synchronously under the lock. Snapshots use one blocking `Simulator::snapshot(path)` that posts a private `SnapshotWork : RunThreadTask`; `SimulatorCore` owns `save_snapshot`/`load_snapshot`, and the daemon owns its own async worker plus request-`id` correlation. `RunControl` stays private to `SimulationRuntime`. Public types are in `runtime_control.hpp`, which is the single enum definition. `simulate()` is `start()` plus `wait()`.
- **Lifecycle:** `start` spawns the single run and blocks until it leaves initialized (running or terminal); `pause` and `resume` gate at macro-step boundaries; `stop` is idempotent once stopping or terminal and preserves partial results, while the teardown `RunControl::request_stop()` cancels a pre-run state to stopped; terminal states are monotonic. `wait` returns `completed`/`stopped` and rethrows failure. States are created, initialized, running, paused, stopping, completed, stopped, failed (`REQ-016`).
- **Publish and flush:** `publish_time()` publishes a step time without pacing, ignores terminal states, advances simulation time monotonically even while stopping, and applies due commands only when not stopping. `RunControl::finish()` returns the effective result; `SimulationRuntime::run()` has one epilogue shared by every exit path: it closes run work exactly once (cancelling tasks still queued) before the recorder flush, then publishes the last completed time, so a completed run reports its end time. The result is finalized after the flush, so a stop requested during the flush is observed; a flush failure publishes failed and still unblocks `wait`; a failure before the run starts publishes failed.
- **Speed:** `set_speed` sets a finite wall-clock factor (`0` free-running, `1` realtime) used by `RunControl` pacing. Variable overrides (`y = k*x + m`) are planned/deferred and are not in current releases.
- **Scheduling:** any control operation carrying `at_sim_time_ns` is deferred to the first macro-step boundary at or after that simulation time; activation granularity is one macro step and deferred operations preserve post order. `pause`, `stop`, and `set_speed` expose the option, while `resume` does not; override-command scheduling is planned with the deferred override feature.
- **Jacobi variants:** `jacobi_serial`, `jacobi_parallel_fut` (std::future), `jacobi_parallel_spin` (spin-wait), `jacobi_parallel_tbb` (TBB task group); all FMUs step concurrently on previous-step values.
- **Seidel variants:** `seidel_serial`; `seidel_parallel` is not implemented — selecting it throws at config selection.
- **la2 (loop-aware):** factory-assembled stack, not a class — SCC detection, one `LinearSubstepExecutor` or `GeometricSubstepExecutor` per loop SCC, the condensed component DAG run by an outer `SerialSeidel`, and a mixed-policy `La2DataAccessResolver` (cross-SCC Latest, intra-SCC StartTime). Outer `ParallelSeidel` (`la2.parallel`) is not implemented and throws during stack assembly.
- **Sub-step executors:** `LinearSubstepExecutor` splits the macro step into equal sub-steps (`iterations`); `GeometricSubstepExecutor` shrinks sub-steps, each covering `factor` of the remaining time until the remainder is at or below `threshold`, then takes the rest of the macro step whole.
- **Include boundary:** `src/lib/include/simulation/executor/` — `executor_base.hpp`/`.cpp`, `executor_utils.hpp`, variant subdirs `jacobi/`, `seidel/`, `loop_aware/`, `substep/`, `custom/`; `ExecutorBuilder` sits one level up at `src/lib/include/simulation/executor_builder.hpp`; the run queue lives with the run loop in `src/lib/include/simulation/runtime/`.
- **Dependencies:** `utils/` (task thread pool, ring buffer, time conversion), `model/` (FmuModel invocation interface), and `signal/` (typed storage used for recording).
