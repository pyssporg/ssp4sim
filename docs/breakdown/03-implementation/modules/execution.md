# execution module

Provides executor strategies that advance simulation time and coordinate FMU stepping, selected by configuration, plus the run-control state machine that starts, pauses, resumes, stops, and paces a run.

- **Role:** `ExecutionBase` defines the executor interface; `ExecutorBuilder` creates the configured executor; strategy pattern, one concrete strategy per algorithm. Executors are pure time-step runners: `SimulationRuntime::run()` owns the outer macro-step loop, takes a due action from `runtime::ControlChannel` at each loop top, else calls `SimulatorCore::step()` for one configured step when Running, and invokes the executor on that step.
- **Engine split:** `Simulator` (`src/lib/public_include/cpp_api/simulator.{hpp,cpp}`) is the caller-facing facade: it retains the creation config, exposes start/pause/resume/stop/set_speed/info/wait/shutdown plus the blocking `snapshot`/`restore` entry points and `reset`, and delegates to the internal `SimulationRuntime` (`src/lib/include/simulation/runtime/`), which owns the run thread, pacing, `RunState`, terminal result, `wait`/join, and the outer loop; the facade is the sole action producer and posts through the runtime's `ControlChannel`, while the runtime only consumes and applies actions. `SimulatorCore` (`src/lib/public_include/cpp_api/simulator_core.{hpp,cpp}`) is the synchronous core: SSP import, graph, executors, recorder, simulation time, one macro step, and `advance_to` for exact-time callers. `src/lib/include/simulation/runtime/control_channel.{hpp,cpp}` holds `ControlChannel`, the single locked queue and status object: one mutex and one condition variable guard `RunState`, simulation time, speed, applied sequence, last error, and one `std::multimap<due_ns, Action>` of `Start`, `Pause`, `Resume`, `Stop`, `SetSpeed`, `SetOverride`, `ClearOverride`, and `Snapshot` actions, plus a closed flag. Only the runtime writes `RunState`. `post()` is fire-and-forget; `post_and_wait()` enqueues and blocks for the applied result. `PacingClock` is the separate collaborator: speed, wall/simulation anchors, and pure deadline math; it stores no simulation time. Public types are in `runtime_control.hpp`, which is the single enum definition. `simulate()` is `start()` plus `wait()`.
- **Lifecycle:** `start` spawns the single run thread, posts `Start` with `post_and_wait`, and returns when the channel reports Running or terminal; a start failure publishes Failed and `wait()` rethrows it. `pause` and `resume` gate at macro-step boundaries; `stop` is idempotent once stopping or terminal and preserves partial results, while teardown posts `Stop` for a started run or publishes Stopped directly before the run starts. Terminal states are monotonic. `wait` returns `completed`/`stopped` and rethrows failure. States are created, initialized, running, paused, stopping, completed, stopped, failed (`REQ-016`).
- **Publish and flush:** `publish_time()` advances the published simulation time monotonically from the core's `sim_time_ns`. `SimulationRuntime::run()` takes a due action, else steps while Running, else waits on the channel condition variable for an action or the pacing deadline. One epilogue is shared by every exit path: it closes the channel (settling blocked waiters), publishes the final time, flushes the recorder, then publishes the terminal state. A flush failure publishes Failed and still unblocks `wait`; a failure before the run starts publishes Failed.
- **Speed:** `set_speed` sets a finite wall-clock factor (`0` free-running, `1` realtime) applied as a `SetSpeed` action; the loop updates `PacingClock` and publishes the new speed.
- **Overrides:** `SimulationRuntime::init()` builds an immutable `(side, model, name) -> scalable` index from the initialized graph; `Simulator::set_override`/`clear_override` validate against it on the caller thread and post `SetOverride`/`ClearOverride`. The run loop writes a per-connector `optional<Override>` only at a macro-step boundary, and `FmuModel::pre`/`post` applies it to the input/output storage before the recorder snapshot. No override mutex is needed: writes happen between steps and `pre`/`post` only read. `list_overrides` is daemon-owned.
- **Snapshot:** `Simulator::snapshot(path)` returns `false` outside Running/Paused; otherwise it posts a `Snapshot` action with `post_and_wait`. The loop calls `SimulatorCore::save_snapshot` at the macro-step boundary, settles the action, and the call returns whether the save succeeded. `SimulatorCore::save_snapshot`/`load_snapshot` own the format and validation; the daemon owns its async worker plus request-`id` correlation.
- **Scheduling:** an action with `at_ns == 0` applies at the next loop top; a non-zero due time defers it to the first loop top at or after that simulation time, so activation granularity is one macro step and equal due times preserve post order. `pause`, `stop`, `set_speed`, `set_override`, and `clear_override` expose the option, while `resume` does not; immediate calls use `post_and_wait` and block until applied.
- **Jacobi variants:** `jacobi_serial`, `jacobi_parallel_fut` (std::future), `jacobi_parallel_spin` (spin-wait), `jacobi_parallel_tbb` (TBB task group); all FMUs step concurrently on previous-step values.
- **Seidel variants:** `seidel_serial`; `seidel_parallel` is not implemented — selecting it throws at config selection.
- **la2 (loop-aware):** factory-assembled stack, not a class — SCC detection, one `LinearSubstepExecutor` or `GeometricSubstepExecutor` per loop SCC, the condensed component DAG run by an outer `SerialSeidel`, and a mixed-policy `La2DataAccessResolver` (cross-SCC Latest, intra-SCC StartTime). Outer `ParallelSeidel` (`la2.parallel`) is not implemented and throws during stack assembly.
- **Sub-step executors:** `LinearSubstepExecutor` splits the macro step into equal sub-steps (`iterations`); `GeometricSubstepExecutor` shrinks sub-steps, each covering `factor` of the remaining time until the remainder is at or below `threshold`, then takes the rest of the macro step whole.
- **Include boundary:** `src/lib/include/simulation/executor/` — `executor_base.hpp`/`.cpp`, `executor_utils.hpp`, variant subdirs `jacobi/`, `seidel/`, `loop_aware/`, `substep/`, `custom/`; `ExecutorBuilder` sits one level up at `src/lib/include/simulation/executor_builder.hpp`; the run queue lives with the run loop in `src/lib/include/simulation/runtime/`.
- **Dependencies:** `utils/` (task thread pool, ring buffer, time conversion), `model/` (FmuModel invocation interface), and `signal/` (typed storage used for recording).
