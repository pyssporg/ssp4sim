# REQ-009: Multiple Embedding API Surfaces

The engine MUST expose simulation through three embedding surfaces: the CLI application, a C API, and Python bindings. All surfaces drive the same lifecycle against the same JSON configuration.

- **CLI:** performs init and simulate, exits with a status code; a version flag prints the version.
- **C API:** exposes create, init, simulate, destroy, and last-error retrieval, plus the implemented runtime-control symbols (`REQ-016`); override symbols are planned/deferred and not in current releases.
- **Python:** `Simulator` exposes a config-path constructor, `init()`, `simulate()`, and the implemented runtime-control methods (`REQ-016`); override methods are planned/deferred and not in current releases.
- **One-shot flow:** `simulate()` remains `start()` followed by `wait()`, so existing callers keep the same blocking behaviour and exception mapping.
- **Consistency:** all surfaces execute the same lifecycle against the same configuration.
- **Use cases:** `UC-003`, `UC-017`, `UC-011` through `UC-016`.
