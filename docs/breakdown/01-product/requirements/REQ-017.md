# REQ-017: External Runtime Access over a Local Socket

The product MUST provide a local external access surface so a separate process can control and observe the same engine without embedding it, and the engine MUST NOT open a network listener.

- **Implementation status:** the daemon, lifecycle commands, speed, scheduling of those commands, and reset/shutdown are implemented. Override commands (`set_override`, `clear_override`, `list_overrides`) are planned/deferred and are not in current releases.
- **Transport:** `ssp4simd` serves a Unix domain socket (or an equivalent local IPC transport) with owner-only permissions, replaces a stale socket path, refuses to start beside a live server on the same path, and unlinks the socket on clean shutdown and on SIGTERM/SIGINT.
- **Framing:** newline-delimited JSON, one object per line with a 1 MiB message limit; every request carries a protocol version (`"v":1`), an optional correlation `id`, and a string `cmd`; responses echo the `id` and events carry none.
- **Commands:** `start`, `pause`, `resume`, `stop`, `state`, `set_speed`, `reset`, and `shutdown` are implemented; `set_override`, `clear_override`, and `list_overrides` are planned/deferred and not in current releases. The control commands expose the `REQ-016` semantics unchanged, including scheduled `at`.
- **Override validation (planned):** `set_override` and `clear_override` identify a target by `(side, model, name)`; the engine rejects an unknown model or name with `unknown_variable`, and `set_override` rejects a type it cannot scale with `unsupported_type`.
- **Override listing (planned):** `list_overrides` returns only overrides active at the current simulation time as `{side, model, name, k, m}`, sorted by side, model, and name; an action scheduled with `at` but not yet activated is not listed.
- **Events:** `state`, throttled `time` progress, terminal `done`, and `error` events are pushed to every connected client; `time` events are droppable, the others are not.
- **Concurrency:** one active simulation per daemon; any connected local client may issue commands; the daemon accepts at most eight clients and serves them from one single-threaded poll loop.
- **Lifecycle:** `reset` stops and waits for a live run, rebuilds the simulator from the same config, initializes it, and resets control state (including overrides once that deferred feature lands); `shutdown` stops and waits for a live run, closes clients, unlinks the socket, and exits.
- **Trust boundary:** access is local-host only and relies on filesystem socket permissions; remote authentication and remote clients are not promised.
- **Use cases:** `UC-026`.
